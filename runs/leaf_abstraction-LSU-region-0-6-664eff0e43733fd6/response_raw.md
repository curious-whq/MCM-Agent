    "DCacheRequest is the only boundary milestone promoted from the two physical request-side events because io.dmem.req.fire represents actual acceptance; io.dmem.req.bits[0].valid is only the lane-level offer and does not by itself establish a memory operation.",
    "A1 follows the actual priority when/elsewhen construction of dmem_req[0].     "LoadExecuteRequest, LoadRetryRequest, StoreCommitRequest, LoadWakeupRequest, HellaIncomingRequest, and HellaWakeupRequest are retained because they distinguish initial execution, retry/re-execution, committed stores, and the independent HellaCache path; collapsing these paths would erase retry and ordering behavior relevant to weak-memory analysis.",
    "A2-A7 preserve the address source selected on every request path. In particular, initial/retry loads use translated exe_tlb_paddr, load wakeups reuse the LDQ-resident physical address, stores use the STQ execute/commit address, and Hella replay uses the retained hella_paddr.",
    "A8-A13 preserve the externally visible distinction between ordinary LSU traffic and HellaCache traffic. A14-A17 additionally preserve the Hella command and access-size fields, which determine the memory operation presented to the DCache.",
    "StoreNeedsOrder records the local fence-driven ordering condition: a valid committed STQ-head fence that observes !io.dmem.ordered requests downstream ordering instead of allowing normal queue progress.",
    "RetryOrderBlock and WakeupOrderBlock preserve the registered form of store_needs_order that explicitly suppresses load retries and load wakeups in the following scheduling stage. A18 and A19 state only exclusion, not eventual progress.",
    "UncacheableWakeupOrderBlocked captures the additional ordering gate for an uncacheable load wakeup.     "LDQ/STQ allocation bookkeeping, individual order-fail updates, nack recovery writes, queue-head movement, and scheduler resource bookkeeping are deliberately omitted unless they directly determine one of the exported request classes or ordering predicates.     "No transaction identity key is introduced because this region exposes request generation but no later completion occurrence that requires a cross-cycle same-request relation.
